# 0.4.1 修复与验证

日期：2026-10-18～19。面向 Windows 11 x64。报告对应 0.4.1 安装包与便携包；[GitHub Release](https://github.com/Karl-Dai/ClipNest/releases/tag/v0.4.1) 提供下载，此版本未代码签名。

本机实测系统为 Windows 11 专业版 x64，系统构建 26300；这不代表已覆盖所有 Windows 11 版本与硬件。

## 修复内容

1. **长文本加载**：列表只查询最多 161 字符的摘要与元数据；正文通过 ID 按需读取。搜索在后台串行执行，输入防抖 180 ms，取消的旧请求不能覆盖新结果。共享存储的版本未变时，窗口的一秒定时器不查询数据库。
2. **完整历史访问**：首批 100 条，继续滚动、点击“加载更多”或向下选择末项时读取后续批次。显示已加载数量与匹配总数，排序以时间和 ID 确保相同时间戳下分页稳定。已加载收藏不受普通历史上限截断。
3. **立即应用上限**：设置与删除超限普通记录在同一 SQLite 事务提交，随后删除对应图片文件；收藏不参与裁剪。即使采集线程预先读到了旧上限，写入时也会采用事务内的最新设置。降低上限时显示“保存并清理”，默认焦点改为取消。

本地数据文件使用 WAL，以减少读取对采集写入的阻塞；UNC 路径保持原模式。
图片预览使用保持比例、双向受限的解码尺寸，生成实际大小受限的位图；只允许一个预览解码在途，过期选择不发布结果。
预览 LRU 缓存最多 4 张，缩略图缓存最多 48 张。完整图片文件不改变，复制仍读取原始图片。

诊断构建会临时保留窗口可见以便测试，并使用独立单实例键。正常发行构建不包含这些测试入口；打包脚本强制关闭诊断编译，并检查程序集不含 `RunDiagnosticsAsync`。
已完成的剪贴板与图片测试原始计数见 [冒烟测试 JSON](performance/2026-10-18-runtime-smoke.json)。

## 内存与查询基准

同一份 1,028 条测试记录（约 1,000 条长文本）展示约 15 秒，两个版本的 30/30 次采样均可见：

| 版本 | 工作集峰值 | 私有内存峰值 |
|---|---:|---:|
| 0.4.0 | 715 MiB | 687 MiB |
| 0.4.1 | 211 MiB | 181 MiB |

这是预热文件缓存、单机、短时观测，不是跨硬件的内存保证。新版使用诊断构建保持窗口可见；同期还运行了后台持续测试与数据库基准。
原始观测见 [新版 UI 数据](performance/2026-10-18-fixed-ui.json) 和 [旧版报告](performance-2026-10-18.md)。

同一次查询基准中，旧完整列表接口取 500 条长文本分配约 62.7 MiB，新的首批 100 条摘要约 65.2 KiB，P95 约 5.1 ms。
首批数量不同是分页设计的一部分。额外测量 500 条摘要约分配 0.29 MiB，该项发生在插入基准之后，记录构成略有不同。
匹配总数与正文检索仍可能全表扫描，极端长文本搜索的 CPU 耗时没有被消除；它们已移至后台，避免阻塞 UI。
完整数据见 [数据库 JSON](performance/2026-10-18-fixed.json)，复现方法见 [工具说明](../build/perf/README.md)。

## 一小时持续运行

**通过：2026-10-19 北京时间 09:21～10:21，完整连续运行 60.02 分钟，715 次循环与资源采样，零项失败。**

10 月 18 日的持续测试没有最终报告，最后可核验进度为 38.23 分钟；之后电脑重启。该轮不算一小时通过。10 月 19 日使用新的隔离数据重新完成完整 60 分钟，指定 `-SkipClipboard`，仅跳过前一天已验证的系统剪贴板改写阶段。新的结果明确记录此选项，不能据此宣称重新跑过快速复制。

| 一小时负载中的指标 | 实测 |
|---|---:|
| 采样间隔最大值 | 5.11 秒 |
| 工作集采样范围 | 238.95～259.09 MiB |
| 私有内存采样范围 | 197.29～214.52 MiB |
| 首次 / 最后一次私有内存 | 198.30 / 203.37 MiB |
| 进程 CPU 累计增量 | 31.63 秒 |
| 平均 CPU，以单核 100% 计 | 0.88% |
| 预览缓存最大条数 | 4 |

没有出现随时长持续上升的内存趋势；一小时观测不能证明所有负载都没有泄漏。上表峰值来自约 5 秒一次的采样，可能错过更短暂的分配峰值。
本轮开始时重新完成 240 次逐张大图切换与 80 次重叠选择，预览切换 P95 32.39 ms、最大 46.88 ms（包含异步调度与 10 ms 状态轮询，并非纯解码耗时）。结束时立即裁剪到 10 条普通记录、保留 13 条收藏，所有保留图片文件均存在。
完整计数与 715 个样本见 [一小时测试 JSON](performance/2026-10-19-runtime-soak.json)。

工作负载每约 5 秒切换大图预览、检查缓存上限、读取历史状态并记录进程内存与 CPU；每约 50 秒写入一条独立测试记录。
默认完整诊断流程在快速复制阶段结束后恢复正常安装版，持续测试实例转入后台并保留真实监听器。本次单独的一小时复测全程保留原正常应用运行。持续阶段不周期性改写用户剪贴板。
两个实例使用独立的数据目录、单实例键与快捷键。测试目录可能收到使用电脑时的新剪贴板事件，所以不公开测试数据库、图片或应用日志。
最终报告只包含测试计数、时间、资源采样和校验结果。

该负载验证后台程序、预览解码和持久化的持续运行；窗口隐藏时不代表持续前台绘制压力，也不等于 8–24 小时或睡眠恢复验收。
